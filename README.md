# opencode-plugin-ntfy-sh

An [opencode](https://opencode.ai) plugin that:

1. **Exposes the opencode server through a Cloudflare tunnel** when it starts. By default this is a quick tunnel with an autogenerated `*.trycloudflare.com` hostname. You can configure a named tunnel or a fixed public URL instead.
2. **Sends [ntfy](https://ntfy.sh) push notifications** when a session:
   - finishes its current task (`idle`)
   - asks a question (`question`)
   - needs a permission approved (`permission`)
   - hits an error (`error`)

Each notification links straight to the session in the opencode web UI, through the tunnel, so you can answer the question or send more prompts from your phone.

## ⚠️ Security

The tunnel puts your opencode server on the public internet. That server can run shell commands and edit files. Before you use this plugin:

- Set `OPENCODE_SERVER_PASSWORD` so the server requires a login.
- Use a long, random ntfy topic, or a protected topic with an access token. Every notification contains the tunnel URL.
- For named tunnels, consider putting [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/policies/access/) in front of the hostname.

## Requirements

- Nothing extra for the tunnel: the [`cloudflared`](https://www.npmjs.com/package/cloudflared) npm dependency supplies the binary. It is downloaded at install time, or on first start if the install script was skipped (Bun skips untrusted postinstall scripts). Set `tunnel.binary` to use a system copy instead.
- An opencode server listening on a real TCP port:
  - `opencode serve --port 4096`
  - `opencode web`
  - `opencode --port 4096`

  If there's no port, the plugin can't tunnel. It still sends notifications, but without a link.

## Installation

Clone the repo, run `npm install`, and reference `src/index.ts` by path in `~/.config/opencode/opencode.jsonc`:

```jsonc
{
  "plugin": [
    ["/path/to/opencode-plugin-ntfy-sh/src/index.ts", {
      "ntfyUrl": "https://ntfy.sh/my-long-random-topic"
    }]
  ]
}
```

Restart opencode after changing the config.

## Configuration

Each setting is resolved in this order; the first source that has it wins:

1. Plugin options (the second element of the `plugin` tuple above)
2. `~/.config/opencode/remote-notify.json`
3. Environment variables

| Option | Env var | Default | Description |
| --- | --- | --- | --- |
| `ntfyUrl` | `OPENCODE_NTFY_URL` | — (**required**) | Full topic URL, e.g. `https://ntfy.sh/topic` or a self-hosted server |
| `ntfyToken` | `OPENCODE_NTFY_TOKEN` | — | Bearer token for protected topics |
| `tunnel.enabled` | `OPENCODE_TUNNEL=0` to disable | `true` | Start cloudflared |
| `tunnel.binary` | `OPENCODE_CLOUDFLARED_BIN` | bundled (npm `cloudflared`) | Path to a cloudflared binary to use instead of the bundled one |
| `tunnel.token` | `OPENCODE_TUNNEL_TOKEN` | — | Named-tunnel token (`cloudflared tunnel run --token`) |
| `tunnel.hostname` | `OPENCODE_TUNNEL_HOSTNAME` | — | Public hostname routed to the named tunnel |
| `tunnel.publicUrl` | `OPENCODE_PUBLIC_URL` | — | Use this URL as-is and don't start cloudflared |
| `notifyOn` | — | `["idle","question","permission","error"]` | Events that trigger a notification |
| `includeSubagents` | — | `false` | Also notify for child (subagent) sessions |

Example `~/.config/opencode/remote-notify.json`:

```json
{
  "ntfyUrl": "https://ntfy.sh/my-long-random-topic",
  "tunnel": { "token": "eyJ...", "hostname": "opencode.example.com" }
}
```

### Tunnel modes

- **Quick tunnel (default):** runs `cloudflared tunnel --url http://127.0.0.1:<port>`. The hostname is random and changes on every start.
- **Named tunnel:** set `tunnel.token` and `tunnel.hostname`. In the Cloudflare dashboard, route the hostname's ingress to `http://localhost:<port>`, and start opencode on that same fixed port.
- **External:** set `tunnel.publicUrl` if you already expose the server some other way, such as a reverse proxy or Tailscale Funnel.

## Notification contents

- **Title:** event type and session title
- **Body:**
  - finished: the last assistant message
  - question: the question and its options
  - permission: the permission and its patterns
  - also: the project directory and session ID
- **Click / action button:** `<publicUrl>/<base64url(directory)>/session/<sessionID>`, which opens the session in the web UI

Notifications for the same session and event within 5 seconds are de-duplicated.

## Restarting the tunnel without restarting opencode

Send `SIGUSR1` to the opencode server:

```sh
kill -USR1 "$(pgrep -f 'opencode serve')"
```

The plugin will:
1. stop the current tunnel;
2. reload `src/core.ts`, so code changes take effect;
3. re-read `remote-notify.json`;
4. start a new tunnel and send a new "opencode server online" notification.

Sessions and running agents are not affected.

> [!WARNING]
> Only send `SIGUSR1` to a server that started **with this version of the plugin loaded**. A process with no `SIGUSR1` handler is terminated by the signal. To check, run `grep SigCgt /proc/<pid>/status`; bit 9 (`0x200`) must be set.

`src/index.ts` is a thin wrapper that hands opencode stable hook functions and forwards them to the currently loaded `src/core.ts`. Changes to `src/index.ts` itself still need a full restart.

## Development

```sh
npm install
npm run typecheck
```

When the tunnel comes up, the plugin sends an **"opencode server online"** notification with the public URL.

`opencode serve` does not print plugin output to the terminal. The plugin writes to opencode's log (`service=ntfy-sh`) instead:

```sh
grep 'service=ntfy-sh' ~/.local/share/opencode/log/opencode.log
```

To also see the log lines on the terminal, run `opencode serve --print-logs`.
